# Personal Agent v3：实现与验收记录

日期：2026-10-08。实现分支：`codex/personal-agent-v3`。范围：本地真实链路和桌面 Chrome；未部署生产。

## 已实现

- 对话是主入口，默认接续最近对话；新对话单独打开。移除首页待审核草稿聚合、推荐稿主导航和旧 overview API。
- 已明确授权的 JD、反馈和文档修改直接保存；用户明确要求预览才保留预览。原 JD、来源记录及文档版本继续保留。分析请求不写资料。
- 来源按钮和回答内的已知来源链接打开右侧资料面板；支持候选人、JD、关联记录、文件原文和已保存成果，保留对话及输入框。
- JD 与候选人复用 PostgreSQL embeddings 表。更新后旧索引退出检索，重新建立索引；返回真实覆盖范围，不能将相似度等同适合度。
- 一次提醒复用 schedules，由独立 worker 在原对话交付；并发领取去重，支持暂停、改期和用户隔离。周期报告复用已有每周/隔周约定。
- 聊天、成果生成和修订可停止；已停止执行不能晚到提交。保存结果和提醒产生对话未读标记；打开对应对话标记已读。
- 资料检索为长期上下文主体，偏好仅显式保存；没有引入新的记忆服务、知识库服务或工作流引擎。

## 放行边界

这些证据支持上述桌面核心链路，不等于全部发布验收完成：本轮没有重验真实邮件发送、公开分享、所有文件格式、全部错误恢复组合、大规模召回质量或生产部署。周期报告在证据不变时仍生成保存成果，只抑制重复通知；没有增加复杂的变更追踪机制。

## 2026-10-10：以 Agent 为核心的资料维护与成果交付

产品执行原则：新增资料、补充或纠正资料、准备成果、修订和请求导出均以对话为主要工作入口；资料页用于查看和辅助核对，不要求用户自行拼接表单流程。

- 候选人新增、职位新增及对话资料库的新增入口进入 Agent。移除独立成果准备表单，原准备入口进入带职位上下文的对话；默认请求不再擅自附加“先审核”。已有资料的辅助编辑和用户明确要求的预览仍保留。
- Agent 可从聊天文字创建候选人、定向更新现有候选人字段，复用既有服务、版本检查与来源记录。部分变更中 null 表示不修改，空值表示明确清空；未提及的联系、经历和教育不会被默认值覆盖。姓名/联系方式匹配时阻止意外重复创建；明确确认同名不同人时允许独立保存，不擅自合并。
- 用户可在对话请求 PDF/Word 导出，收到对应成果的下载按钮；已完成成果卡片和对话内预览同样支持导出。复用原有带用户与版本检查的导出接口，下载时生成文件，不将“显示下载按钮”声称为已下载。旧版本导出请求拒绝静默导出另一版本，显示错误并允许刷新。
- 修订规则明确区分标题推断与文稿中明确陈述的事实：仅因来源快照为空，不得无依据弱化已陈述事实；与实际证据冲突的内容仍可纠正。

## 2026-10-10：继续收拢 Agent 主流程（本地真实链路）

本轮检查候选人、职位、沟通记录、关系/授权、定期报告和成果交付入口。没有增加业务实体，没有按测试人名、职位、行业或固定话术分支。

- 候选人/职位页的关联、新增沟通记录、意向与分享授权入口携带上下文回到 Agent。明确授权的关联、意向/备注更新直接保存；缺失关联自动创建，证据记录与关系更新在同一事务提交。普通关联不推断分享授权。空字符串只用于明确清空，未提及字段保持不变。
- 职位名称、客户名称/联系人、暂停/关闭/恢复可直接交代 Agent；要求变化仍保留原 JD。现有资料直接编辑是辅助入口。新增关系和已有关系均保留版本检查、用户隔离和历史。
- 定期更新设置/调整入口回到对话，复用现有 schedules。页面保留暂停/恢复、真实状态和就地重试，不要求填写排程表单。
- 成果页“Deliver to client”携带保存的文档回到 Agent；删除独立 Gmail 收件人表单。具体收件人、内容和附件确认留在对话，保留提供方回执及 unknown 不自动重发约束。公开链接/复制是辅助操作，仍可在成果详情中使用；登录、OAuth 和支付保留各自所需的账号授权界面。
- 站外交付登记改为对话动作，复用 markSubmitted 并支持同事务调用。只保存用户报告的过去交付时间、收件人及渠道，不生成 Gmail 回执、不发信，不修改保存文本。信息缺失时澄清；重复登记不重复产生事件。
- 模型漏填关系引用由结构化校验进入通用修复；简单关系更改没有单独提炼 record 时保留原始用户指令作为来源，不编造事实或报“缺少关联”。明确要求预览时展示实际更改内容，接受时不能替换被预览的写入字段。
