# Personal Agent v3：实现与验收记录

日期：2026-10-08。实现分支：`codex/personal-agent-v3`。范围：本地真实链路和桌面 Chrome；未部署生产。

## 已实现

- 对话是主入口，默认接续最近对话；新对话单独打开。移除首页待审核草稿聚合、推荐稿主导航和旧 overview API。
- 已明确授权的 JD、反馈和文档修改直接保存；用户明确要求预览才保留预览。原 JD、来源记录及文档版本继续保留。分析请求不写资料。
- 来源按钮和回答内的已知来源链接打开右侧资料面板；支持候选人、JD、关联记录、文件原文和已保存成果，保留对话及输入框。
- JD 与候选人复用 PostgreSQL embeddings 表。更新后旧索引退出检索，重新建立索引；返回真实覆盖范围，不能将相似度等同适合度。
- 一次提醒复用 schedules，由独立 worker 在原对话交付；并发领取去重，支持暂停、改期和用户隔离。周期报告复用已有每周/隔周约定。
- 聊天、成果生成和修订可停止；已停止执行不能晚到提交。保存结果和提醒产生对话未读标记；打开对应对话标记已读。
- 资料检索为长期上下文主体，偏好仅显式保存；没有引入新的记忆服务、知识库服务或工作流引擎。

## Chrome 实际操作证据

虚构 PDF：`fictional-jd.pdf`、`fictional-cv.pdf`。以下均在实际应用中操作，没有使用静态原型或预置模型回复。

| 场景 | 实际结果 |
| --- | --- |
| S1 JD 接收 | 混合上传 JD/CV 后，Harbor Analytics 的 Head of Product 直接保存；原文件及原 JD 可读取 |
| S2 简历整理 | Mira Stone 自动保存为候选人，原 CV 和来源记录保留，无通用审核步骤 |
| S3 双向匹配 | 新对话按 enterprise onboarding / permissions 检索已有候选人和 JD，找回两者，给出逐项匹配与未确认条件 |
| S4 沟通准备 | 同一回答给出 3 个基于履历和岗位条件的筛选问题，无待办对象 |
| S5 推荐成果 | 生成内部推荐，随后请求 120 词内修改，直接保存第 2 版；实际面板显示版本，旧版本保留，没有发送 |
| S6 客户反馈 | 明确反馈办公日由 Monday/Thursday 改为 Tuesday/Thursday，当前要求直接更新，原 JD 不变；未被要求修改的旧成果不擅自改写 |
| S7 后续约定 | 在 UI 请求两分钟后提醒；自然等待后 worker 在原对话交付一次。另一对话可看到未读标记，返回后清除；周期报告另有真实集成测试 |
| S8 工作回顾 | 对话归纳本次反馈对候选人的影响，并给出三个优先核实事项，区分已知事实与未确认信息 |

额外验证：停止按钮真实生效、新建对话不自动跳回旧对话、刷新后保存结果仍在、点击回答内来源同屏展开。数据库核对显示提醒消息恰好一条、成果版本为 2，通知已读状态与 UI 一致。

## 放行边界

这些证据支持上述桌面核心链路，不等于全部发布验收完成：本轮没有重验真实邮件发送、公开分享、所有文件格式、全部错误恢复组合、大规模召回质量或生产部署。周期报告在证据不变时仍生成保存成果，只抑制重复通知；没有增加复杂的变更追踪机制。

历史静态原型仍在 [prototypes/personal-agent-v3.html](prototypes/personal-agent-v3.html)，只用于设计对照，不计入本轮实际实现验收。
