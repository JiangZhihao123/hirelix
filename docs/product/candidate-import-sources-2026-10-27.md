# 海外独立猎头：候选人导入来源优先级

核对日期：2026-10-27。用途：决定 Hirelix 冷启动导入先支持哪些来源，不是推荐购买 ATS，也不是独立猎头市场份额排行榜。

## 结论与证据边界

首批优先覆盖 **LinkedIn Recruiter、Loxo、Recruit CRM、Recruiterflow** 的候选人文件。第二批考虑 **Crelate、Zoho Recruit、Manatal**；进一步面向英国和澳大利亚时提高 JobAdder 的优先级。Excel/CSV 和本地简历应作为基础能力，不要求用户先更换 ATS。

这里的排序是产品判断：综合目标人群吻合度、可观察的采用证据、候选人资料可迁出程度和工程成本。未找到可以可靠比较上述产品在“海外独立猎头”细分人群中活跃付费席位的同口径数据，不能声称这是精确热门榜或市占排名。厂商客户数、个人席位数、免费账号、全球所有招聘团队和独立猎头不是同一种统计。

本次 Exa 在采用案例、厂商披露、导出能力三个方向召回 61 条结果（包含重复），再核读相关官方页面和说明。召回数不是逐页全文验证数。排除企业内部 HR ATS 排名和无实证的联盟营销榜单作为排序依据。社区和个人用户反馈只作为人群吻合度线索，不外推市场占有率。

## 采用迹象与支持优先级

| 来源 | 目标人群与可核实证据 | 对 Hirelix 的意义 |
| --- | --- | --- |
| LinkedIn Recruiter / Lite | 官方明确提供 Recruiter 项目导出以及独立的申请人导出；本次找到了独立/小型机构以 LinkedIn 配合 CRM 工作的用户报告。没有取得独立猎头使用率统计。 | 与 ATS 并行的资料来源。优先接 CSV/XLSX/PDF，不能把个人连接名单当 Recruiter 全库。 |
| Loxo | [官方免费 ATS/CRM 页面](https://hiringmachine.loxo.co/free-ats-crm)自称覆盖 13,200 多家 recruiting organizations，但该入口未给统计日期，也不区分免费与付费及机构大小。提供面向猎头的 ATS/CRM，具有小机构采用迹象。 | 首批候选人 CSV；不承诺完整历史，更不能搬走 Loxo Source 全部人才数据。 |
| Recruit CRM | [官方页面](https://recruitcrm.io/blogs/switch-to-recruit-crm/)披露 2,500 多家 agency、100 多国；[First Point Partners 案例](https://recruitcrm.io/blogs/case_studies/first-point-partners-witnesses-placement-surge-using-recruit-crm/)说明其客户从两人 boutique 起步。数量与增长均为厂商自报。 | 人群吻合且全量导出文档明确。候选人名单先支持，多实体备份和关联历史需独立验证。 |
| Recruiterflow | [当前官网](https://recruiterflow.com/)称覆盖 2,100 多家 search firms；[客户页](https://recruiterflow.com/customers)仍有 1,700 与 2,100 两种口径，不能以此直接推算增长或市占。客户案例覆盖独立招聘和 executive search。 | 首批原生 XLSX，全表逐行处理，避免整表摘要造成遗漏。 |
| Crelate | [Tire Talent 官方案例](https://www.crelate.com/blog/case-study-tire-talent)明确为从一人发展到四位猎头的机构，表明适合该人群；该案例时间较早，不代表当前客户规模。 | 北美精品机构重要次序；支持其候选人 Excel，先辨别 candidate 与 client contact。 |
| Zoho Recruit、Manatal | [Manatal agency 页面](https://www.manatal.com/staffing-agencies)称 10,000 个 recruiting teams，包含不同组织类型，不能视为 10,000 家独立猎头公司。Zoho 的导出与备份机制成熟，但本次没有独立猎头采用份额的可靠统计。 | 用通用表格能力覆盖；避免因“低价/总客户多”直接断言在独立猎头中最热门。 |
| JobAdder | [agency 页面](https://jobadder.com/recruitment-agencies/)给出精品猎头、澳洲等机构案例，也服务企业内招聘。 | 面向英国/澳大利亚扩展时提高优先级；本轮不把未经核实的完整导出承诺写进产品。 |

用户证据补充：[两人机构使用 Manatal，并结合 Apollo 与 LinkedIn 的自述](https://www.linkedin.com/posts/kaylarussetto_recruitment-people-id-love-your-recommendations-activity-7477065098881228800-5ksa)、[Recruiterflow 用户对历史资料老化、解析和检索问题的自述](https://www.linkedin.com/posts/lizschrader_fellow-recruiters-what-crms-are-you-using-activity-7422686671646867456-ys7T)。这些是个人报告，不证明普遍比例。

## 官方导出路径与不能承诺的部分

| 来源 | 已核实路径与格式 | 覆盖边界 |
| --- | --- | --- |
| [LinkedIn Recruiter](https://www.linkedin.com/help/recruiter/answer/a412149) | 项目 Pipeline 选人后 Save to CSV；也有 PDF。另有[申请人导出 XLSX / PDF ZIP](https://www.linkedin.com/help/recruiter/answer/a7459505)。 | Lite 不支持 CSV；有选择与月下载限额；CSV 联系方式只含 recruiter 输入内容。不是整库一键无限导出。 |
| [Loxo](https://help.loxo.co/en/articles/1238814-export-people-and-company-records-from-loxo) | Admin 从 People 选人，可跨页选择；Export selected，通过邮件取得 CSV。 | 普通 CSV 不含简历附件、活动历史、工作与教育历史；Source 原生数据另有限额，完整导出受合同约束。 |
| [Recruit CRM](https://help.recruitcrm.io/en/articles/3591116-exporting-all-data-for-recruit-crm-account-owners) | 付费账户 owner 在 Account 发起 Data Export / Full Export，CSV ZIP；Full Export 另含附件。 | 多实体与 notes/assignments/associations 分开；全量备份不是候选人 ZIP。文档未提供可验收的字段级完整样本，本轮不能声称自动重建所有关联历史。 |
| [Recruiterflow](https://help.recruiterflow.com/en/articles/3671789-export-candidate-data-to-excel) | Advanced Search 选中目标候选人，Export to Excel，选择字段，下载 XLSX。 | 只含选择和过滤范围的数据，简历、附件和 notes 不随此导出。 |
| [Crelate](https://help.crelate.com/en/articles/4120416-exporting-contact-data-to-excel) | Contacts → Export，可选 all records / all columns，Excel。 | Contacts 最多 15,000 条，Search 最多 10,000 条；需分辨客户联系人和候选人；完整备份是另一机制。 |
| [Zoho Recruit](https://help.zoho.com/portal/en/kb/recruit/essentials/data-management/request-data-backup/articles/request-data-backup) | Admin 在 Setup → Data Administration → Data Backup 请求 CSV ZIP。 | 多模块不是候选人专用名单；notes、附件单独处理，不能把它们当候选人行导入。 |
| [Manatal](https://support.manatal.com/docs/export-data) | Admin 可导出一个 dataset 为 CSV/XLS，可能需要客服开通；[表格导出](https://support.manatal.com/docs/export-function)还受显示列与当前页面范围影响。 | 页面导出不等于全库；旧 XLS 需要另存为支持的格式，优先选择 CSV。 |

## 当前实现与验证边界

实现支持 CSV/TSV/XLSX 候选人表及候选人文件 ZIP；保留原件、原始行及未知字段，逐工作表映射；已有身份冲突不自动覆盖。ZIP 的候选人变更原子提交。实际限制为每个上传 50 MB、以 2 MB 分片续传；每表/ZIP 10,000 候选人、ZIP 500 文件及 30 MB 解压量。不是不限容量的全库迁移。

已用真实 PostgreSQL 与真实模型验证 1,000 行、多工作表、保留原始字段、索引排队，以及混合 ZIP、身份冲突、后续授权、失败回滚和幂等。测试文件为合成资料，**没有使用以上厂商真实账号导出的完整备份做端到端验收**。官方文件格式说明证明导出路径；通用文件契约和合成样本验证证明读取能力，二者不能合并宣传为每家平台全量历史都已迁移成功。

公开信息寻访、私人库导入和原 Bright 付费召回是不同能力。不能用导入支持或公开搜索绕过已退出产品的旧寻访链路。
