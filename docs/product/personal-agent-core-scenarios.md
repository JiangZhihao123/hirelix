## 产品定位

Hirelix 是替猎头持续推进工作的个人 AI Agent。目标用户是海外英语国家的独立猎头与精品猎头公司顾问，首版聚焦桌面浏览器体验。

用户交给 Agent 的是一个工作目标，以及完成它所需的资料。Agent 理解上下文，执行已授权的工作，交付结果，并能在后续对话中接着推进。

英文产品类别保持 **Personal AI Agent for Headhunting**。长期助理的价值体现在持续理解客户、候选人、职位、工作偏好和明确约定，并在下一次工作中正确使用这些信息。

## 八个核心场景

| 场景 | 用户交代的目标 | Agent 应承担的工作 | 用户获得的结果 |
| --- | --- | --- | --- |
| 接下招聘需求 | “客户要招一个产品负责人，这是 JD 和电话记录。” | 整理真实需求、关键条件、待澄清问题和评估标准；保存客户偏好，并随反馈更新 | 可用于后续匹配和沟通的职位理解，以及真正需要补充的信息 |
| 积累和理解候选人 | “这是今天聊的人，简历和聊天记录都在这里。” | 识别已有候选人，整理经历、能力、意愿与沟通信息；按授权更新档案，保留来源和时间 | 能持续使用的候选人资料，避免重复录入和遗忘历史沟通 |
| 从已有资源中找合适的人 | “我认识的人里，谁适合这个职位？” | 检索用户自己的候选人库，结合具体职位判断匹配度，解释推荐理由、风险和缺失证据 | 有依据的人选建议，包括容易被遗忘的已有候选人 |
| 准备候选人沟通 | “我下午要和 Mira 聊，帮我准备一下。” | 回顾历史沟通，整理本次目标、核实问题和职位介绍；会后接收笔记，按授权更新判断和下一步 | 有上下文的沟通准备，以及会后可以继续推进的工作 |
| 向客户推荐候选人 | “把这三个人推荐给客户，讲清楚各自的优势。” | 根据真实证据形成推荐材料，按客户习惯调整表达，检查对外分享范围，在对话中完成修改与交付 | 可查看、修改、导出或在明确授权后发送的推荐材料 |
| 推进面试和反馈 | “客户觉得她行业经验不够，但愿意再聊一次。” | 将反馈关联到人选和职位，更新评估标准，准备后续沟通与面试材料，明确下一步由谁在什么时候做 | 连贯的推进记录和清楚的下一步，反馈能影响后续工作 |
| 跟进关系和约定 | “他年底才考虑机会，11 月再联系；客户周五要一次进展。” | 记住明确约定，在合适时间提醒或执行已授权的准备工作，带上相关上下文 | 可兑现的跟进和交付，用户无需重新解释前因后果 |
| 回顾工作并安排下一步 | “今天我最该推进什么？” | 汇总正在推进的职位、人选与承诺，识别停滞、到期和等待反馈的事项，给出有依据的行动建议 | 重要事项与具体行动建议，并能继续委托 Agent 执行 |

候选人与职位需要双向连接：既支持“这个职位适合谁”，也支持“这个人适合哪些已有机会”。匹配判断始终属于具体的候选人与职位组合，不建立脱离职位的全局“好候选人”标签。

已有资源匹配以用户自己的资料为基础；本文不恢复已经退出产品的独立外部付费人才寻访链路。

## 贯穿所有场景的五项能力

### 持续对话

用户随时交代目标、补充材料、更正要求或停止执行。Agent 能接着之前的上下文工作，不要求先选流程、建待办或填写准备表。相关工作可以跨对话延续；歧义需要澄清，不把无关历史强行关联起来。

### 资料检索与最小记忆

优先保证上传过的 JD 和简历可检索、可读取原文，并关联候选人、职位及沟通笔记。Agent 在后续对话中按需找回资料，基于具体 JD 判断匹配，保留来源与时间；检索相似度不等于匹配质量。

偏好只保存用户明确要求记住的工作习惯，可修改和删除。首版不做自动记忆提取、冲突仲裁、记忆图谱或全历史自动总结。长期助理的价值先通过资料能找回、能继续使用实现。

### 工具执行

Agent 调用实际能力完成检索、分析、保存、修改、导出和已授权发送。明确授权且无歧义的整理直接完成，只有身份、事实冲突或影响任务的缺失信息才需要询问。分析请求不擅自修改资料。

进度和失败恢复留在对应对话；从资料详情发起时，原页面也能看到状态并继续。完成说明来自真实工具回执，不以准备执行或生成计划冒充完成。

### 长期委托

首版通过自然语言交代指定日期的一次提醒或固定周期进展报告，可调整、暂停和撤销。任意事件触发、邮箱监听和复杂跟进规则暂缓。Agent 保存范围、授权与时间条件，后台执行后回到对话交付；无变化保持安静。

“11 月联系”这类模糊时间需澄清后才能建立确定提醒；没有邮箱读取或事件接入能力时，不能声称正在监听客户回复。

### 成果交付

按目标交付答案、比较、沟通要点、推荐文件或操作回执，不把所有回答变成文稿。用户在对话中继续修改和使用；长内容可打开面板查看、编辑和导出。

成果完成不以用户点击“审核通过”为前提。对外发送、披露私人信息或作出承诺须符合具体授权；制作材料不自动授权外发。已有明确且仍有效的授权不重复询问。

## 首版需要打通的完整工作链

**接需求 → 找到已有候选人 → 准备沟通 → 形成推荐 → 吸收反馈 → 持续跟进。**

优先保证这条工作链的连续性：前一步产生的信息应能被后一步使用，用户能跨对话继续工作，客户反馈能改变后续判断，明确约定能被可靠执行。

工程取舍优先稳定与维护：复用现有 PostgreSQL、检索、业务服务和执行队列。可以接受召回不完整、用户补充上下文、部分分析重新计算；不牺牲原资料保存、用户隔离、来源真实性和副作用去重。没有证据证明必要，不增加服务、实体或模型调用层。

八个场景是能力地图，不要求每个场景对应一个独立模块、入口或页面。具体实现应复用现有资料、对话和执行能力，避免为场景名称增加重复实体。

## 交互与信息架构原则

默认体验是与同一个个人助理持续交流。对话承担交代、执行、交付和接续；候选人库、职位库及成果是可查阅和编辑的支撑资料。

1. **主要入口是对话。** 新用户看到简洁开场与输入框；已有用户可继续最近对话、新建对话或搜索历史。
2. **结果在对话交付。** 后台成果回到所属对话，通过未读标记提醒，不另建待处理队列。
3. **真正的问题直接问。** 在相关对话说清事实歧义或授权缺口，用户自然回复即可；无须进入审批中心。
4. **资料与成果按需打开。** 对话中的对象引用、详情面板和搜索支持核对与编辑，用户不用先管理文稿才能继续工作。
5. **长期委托可控。** 可随时询问约定、暂停或修改，也可从设置查阅；不形成每日必须清空的待办列表。

### 明确剔除的机制

- 首页待办中心、待审核草稿列表、草稿审批队列。
- 以 Needs your input、Due 等名称重新组织同一种用户工作管理面板。
- 所有请求必经“生成草稿 → 审核 → 应用”的流程。
- 用户必须新建、分配、更新或关闭的 Work 对象，以及按八个场景建立的八套流程入口。

现有实现按 `status = draft` 读取最近文稿并展示为“待审核的草稿”，应退出目标设计。仅改成“最近文稿”或“需要关注”不足以完成调整。

用户明确要求写草稿时仍可获得草稿，它是内容用途，不是审批机制。已有资料和成果保留；技术执行状态、持久结果版本和具体动作授权也保留，但由系统承担，不转化为用户维护负担。

例如：“比较这三个人”直接交付比较；“把 Mira 写得详细一点”继续修改；“发给客户”在授权条件满足时调用发送能力。无需先建待办，再认领草稿，然后点审核通过。

## 调研与产品选择

2026-10-08 的 Exa 调研核对了 Lindy、OpenClaw、Claude/Cowork、Manus、Gemini Spark 和 Perplexity Personal Computer 的官方说明。共性是目标委托、上下文积累、实际执行和成果接续，并非所有产品都取消任务列表或确认。

Hirelix 剔除待办与草稿工作流，是本轮产品决定；官方来源和能力边界见[配套方案的调研依据](personal-agent-architecture-and-interaction.md#12-依据与边界)。不能把这一选择表述成未经验证的行业共识。

## 设计与验收时应回答的问题

- 用户能否用工作目标发起任务，而无需先理解产品内部模块？
- Agent 能否使用已有资料和历史反馈，避免让用户重复解释？
- 用户是否知道已经完成什么、还缺什么，以及下一步是什么？
- 用户是否完全无需维护待办、认领草稿或通过通用审批，就能完成已授权的工作？
- 所有确认请求是否对应真实缺失信息或具体动作授权边界，而非机械审批？
- 成果是否已实际保存并可查看、修改和继续使用？
- 跨对话继续工作、约定跟进和失败恢复是否有真实链路证据？

具体功能的上线状态和验证结果应记录在相应验收文档中，不能由本文的目标描述推断。
