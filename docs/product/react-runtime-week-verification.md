# ReAct runtime 与猎头一周工作过程验收

日期：2026-10-11。范围：本地桌面 Chrome、真实 DeepSeek、隔离 PostgreSQL、独立 worker。没有部署生产，没有发送外部邮件，也没有调用已退出产品的付费寻访。

本轮验收关注工作如何连续推进：选择工具、观察结果、保存事实、显示进度、交还判断、停止、纠正、恢复和使用成果。最终表里有数据只是其中一种证据。虚构业务日期为 2026-10-05 至 2026-10-09；实际操作在 10 月 11 日完成，不能称为连续五天的线上运行。

## 八条宪法审计与实现

| 宪法 | 原实现问题与本轮处理 |
| --- | --- |
| ReAct 是智能核心 | 移除一次生成大 JSON 计划再批量执行的聊天执行器。`agent-runtime.ts` 用 AI SDK `ToolLoopAgent.stream` 实现模型调用、真实工具执行、观察结果、下一步选择的循环；结束条件包含完成、等待人类、取消和执行上限。 |
| Tools 提供真实能力 | `agent-tools.ts` 组合现有候选人、职位、记录、文档、提醒、检索和邮件服务。工具返回真实对象、版本、来源链接及可修正的错误，UI 和 Agent 复用业务规则。 |
| 上下文支撑持续工作 | 当前请求、限定长度历史、保存回执、明确偏好、资料索引和按需读取的 Skill 共同构成上下文。修复历史有正文就丢掉回执、取消后丢掉已保存事实的问题。 |
| UI 是共同工作界面 | 工具提交后立即刷新同一消息的成果卡；流式回复、实际进度、失败和停止使用真实生命周期。成果默认折叠，可在对话中打开、编辑、导出；修订后更新旧卡和导出入口。 |
| 人在 runtime 中 | 缺失关键身份时 `ask_user` 暂停，回答后恢复原请求。中断传递到模型和子任务，租约校验阻止晚到提交；已保存部分保留，新指令读取最新状态接管。 |
| 不写业务工作流 | 招聘记录、客户交付、提醒方法放在三个 Markdown Skill 中，由模型按需读取。没有星期一至星期五的路由、阶段机或预设工具序列。明确的用户执行顺序由模型指令约束。 |
| 不为案例写智能代码 | 问题修复落在 schema、来源、授权契约、工具观察、未知事实规则和共享导出器。代码中没有客户名、候选人名、特定薪资或案例关键词分支。 |
| 架构尽可能简单 | 一个 Agent 循环，薄工具层，现有 jobs/messages/schedules。新增 SDK 用于标准工具调用和流式循环；没有新的业务表、工作流引擎、记忆服务或 Agent 团队。现有子任务只增加父聊天归属，不建立通用检查点系统。 |

实现入口：`src/lib/workspace/agent-runtime.ts`、`agent-model.ts`、`agent-tools.ts`、`agent-execution.ts`。Skill 位于 `src/lib/workspace/skills/`。AI SDK 固定在支持项目 Node 20 环境的 6.x，DeepSeek 为默认 provider，OpenRouter 仍只作为配置的备用路径。

工具提交和回执在同一数据库事务内保存；重复参数重放读取已提交回执，授权引用文字不参与幂等键。任务租约失效、停止或父任务结束后，旧执行不能提交业务结果。失败恢复读取现有任务和文档，不把“重试”理解成再创建一份成果。

## 真实 Chrome 的一周工作

全部输入通过产品对话或页面控件完成，读取数据库只用于独立核验。业务素材是两个虚构客户、两位虚构候选人、两个 PDF 简历和两个 DOCX JD。

| 工作阶段 | 过程与实际证据 |
| --- | --- |
| 接收两份 CV 和两份 JD | 上传四文件；模型读取原文并保存两位候选人、两个职位及各自原文件。没有聊天式导入向导，也没有强制逐项审批。 |
| 周一确认两个委托 | 分别保存 Cedar 的到岗/面试要求和 Beacon 的轮值/面试要求。更新职位保留原 JD、已有要求和未确认字段。 |
| 周二候选人沟通 | 故意不说明是哪位候选人的薪资，Agent 提问且不写入；回答后继续保存原通话和明确的职位限定分享许可。Owen 的兴趣、薪资、通知期与尚未确认的许可分开保存。 |
| 周三连续跟进和纠错 | Maya 的第二次通话单独保存；之后把同一次通话中的薪资改为 155,000，只更新第二条记录。CV 中带领四人与通话中五人的差异保持可见。 |
| 准备推荐稿 | 使用明确授权的来源，保留未知事实，排除内部现薪。生成故障回到对话，修复后复用原失败任务恢复，没有新增成功文档替代原任务。 |
| 人工编辑后继续 | 在文档页面修改标题并保存，再回到对话要求缩短。修订使用最新标题与版本，推荐稿最终为第 3 版，早期版本保留。 |
| 周四客户变更 | Cedar 只降低薪资上限；Beacon 只调整轮值。两个客户反馈不混合，原 JD 不改写，当前职位要求为第 4 版。 |
| 周五推进与交付 | 保存 Owen 的新通话、职位限定许可及下周计划面试；生成两份 5–9 日周报。计划面试没有被写成已完成面试；实际活动与建议下一步分开。 |
| 导出与检查 | 在真实页面下载推荐稿及两份周报的 PDF/DOCX。检查实际文件正文及 PDF 页面；没有将接口成功替代文件检查。 |
| 提醒 | 约定提醒在实际 10:15 UTC 到点后进入原对话，检查了消息和保存状态。没有通过修改 due time 冒充自然到点。 |
| 新对话接续 | 重新找回最新职位、候选人状态、许可和周报，读取没有产生业务重复记录。新对话标题由目标命名。 |
| 中断、部分保存、继续 | 先把 Beacon 跟进日期改为 14 日，观察保存卡出现，再停止内部评估的长文修订。记录更新保留，子修订取消，内部评估仍为第 1 版。后续只读请求继续使用已保存状态。 |

主对话 ID：`3ca62340-f483-4864-bf23-613e27ab0521`；新对话接续 ID：`8177c62f-6b46-4a6e-bd89-fc2a7aa3777e`。这些仅存在本地 QA 库，不是生产链接。

最终业务读回：两位候选人、两个职位、四次独立候选人通话、两条职位限定许可、两份最新周报、一份推荐稿和一份内部评估。另有客户反馈、JD 版本记录、计划面试和内部跟进记录；后两者不能当成已完成活动。

## 实际发现并修复的问题

- 更新职位时缺失字段被默认补成空数组，导致旧要求丢失：Agent 专用 schema 要求完整 brief，null 才代表不修改；可引用同职位已存在反馈，不重复生成客户通话。
- 上传的客户备注在后续授权保存时丢失文件来源：工具显式传递原文件 ID，JD 与备注保留各自来源和时间。
- 长文工具超过步骤超时后，过渡文本被当成完成回复：移除覆盖整个子工具的短步骤超时，保留模型请求与整轮边界；处理中断事件并验证最终结束原因。
- 继续失败工作时找不到旧任务 ID：历史保留已提交回执；`resume_work` 复用既有任务，并检查会话、归属和重试状态。
- 坏 PDF 异常终止整批处理：非取消类异常变为工具观察，模型继续其他独立文件；坏文件仍明确失败，没有伪造提取成功。
- 取消后残留正在生成的成功声明：清除未提交的 live reply；保存卡保留。停止同时取消子任务，阻止晚到写入。
- 已恢复成果卡、修订后下载入口仍显示旧状态：终态事件刷新相应任务和文档，默认收起全文，减少重复内容。
- 澄清问题和用户答案重复展示：问题卡承担决策交互，选项使用原生 radio，不再重复同一正文。
- 模型把没有记录推断为没有发生/没有安排：通用证据规则、Skill 和文档生成规则要求保持未知。周报与新对话实际复核。
- 模型构造不存在的文档 URL：读取工具返回准确 href，并注册来源，链接可打开真实文档或对话内资料面板。
- 周期报告把职位要求误当作私有沟通记录：分别描述两个 inclusion 字段；错误指出具体引用字段及当前请求，模型可以在同一轮修正，不能把明确指令误报成用户未授权。
- PDF 短段落跨页留下孤行：共享导出器在整段能放进一页时保持段落连续，重新下载并渲染检查。

没有改写旧 QA 对话来掩盖失败。早期错误回答、停止状态和修复后的继续操作都保留在 QA 数据中。

## 验证与边界

本地 UI 数据库：`hirelix_workspace_qa_react_week_20261011`。自动回归单独使用 `hirelix_workspace_qa_two_by_two_regression_20261011`，防止浏览器 worker 抢领测试任务。所有 LLM 集成测试都使用真实模型，数据库测试使用真实 PostgreSQL。

自动检查结果和最后一次真实链路结果见下方最终记录。单元测试只证明局部契约，真实 PG 的主动取消/故障注入只证明执行边界；它们与实际 Chrome、模型调用、保存读回和导出文件是不同层的证据。

证据保留于本机 `output/react-runtime-20261011/`：真实链路日志、按阶段读回 JSON、导出正文和渲染图、提醒与中断截图。原始四份上传素材在 `output/two-cv-two-jd-20261011/fixtures/`。这些输出含测试数据并保持 Git 忽略。

这次没有验证生产部署、真实收件人的邮件发送、全套发布验收或移动端。周期报告的创建/暂停/恢复/执行由真实模型加 PG 回归验证；实际 Chrome 的自然到点验证针对一次提醒，不能宣称经过一周周期调度的线上观察。
