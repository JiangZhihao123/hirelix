## 本轮完成

### 强杀后的工作区资源

修复 `961454ad` 接入现有 worker 定时维护。资源携带产品、数据库身份、job 和租约标记；使用 Docker daemon 时间判断五分钟宽限期，且原租约必须经既有 reclaim 清除或替换。容器按 ID、卷按名称二次校验元数据；不同数据库、未知标签、仍持有相同租约的资源不清理。数据库或 Docker 不可用时保守保留并记录错误。旧版缺少数据库身份标签的资源、或数据库身份变化前遗留的资源需要人工核查；不会用全局 prune。

实际运行的独立子进程先建立临时工作区和长命令，再以 SIGKILL 终止；观察到 run、lock、keeper 和卷残留（`output/recovery-qa/kill-before.json`）。真实 PG/Docker 长测完整等待五分钟，依次证明未过期保留、活跃租约保留、已到期但尚未 reclaim 的原 token 保留、实际 reclaim 后领取新租约、旧资源回收、新资源不受影响、相同回执重放不重复写入、已提交文件保留及重复回收安全；其他 Docker 工作负载与不同数据库标签保留。最终 1/1 通过（`recovery-test-final.log`）；数据库不可用 1/1 通过（`recovery-unavailable.log`）。初次旧版残留在确认仅属于本次测试后按准确 scope 手工清理（`legacy-cleanup.json`）。

当前还没有在生产 Linux/systemd 环境强杀整个 scheduler 后验证实际重启和定时器运行；上述是实际子进程、数据库租约和 Docker 的受控验证，不是生产恢复证明。旧结果和账本的端到端持久性亦只能按各项现有回执/数据库证据说明，不能推断全部自然模型恢复场景。

### 多实体与规模

真实 PG/Docker 的现有受控契约回归 9/9 通过（`output/recovery-qa/current-contracts.log`）：真实多 sheet XLSX 转换、来源、原文件、身份冲突与部分失败、角色/人选/记录/附件、版本与用户隔离、租约失效后的已提交批次、重放、停止和无 Docker 显式失败。自然语言身份判断不由这些直接服务测试证明。

新增 `3f1f02bc` 使用一个 6,746 字节的合成 ZIP：Docker 解析 501 行，实际保存 500 位不同候选人并明确报告 1 条身份冲突；重复提交全部返回冲突，已保存的人数不增加。另保存 500 条关联备注及 25 个原件；逐条核对备注的原始 ZIP 路径/行号，逐件核对抽取附件的身份、原路径与原字节，日期未知保持未知。随后精确领取 500 个索引任务，真实 PG 写入 1,525 个片段并作后续检索和跨用户空结果检查；向量由受控替身生成，不代表真实 embedding 模型的语义质量或成本。

最终 1/1 通过（`distinct-scale-final.log`）：保存和重复处理约 4.19 秒，500 个受控索引任务约 1.58 秒，采样 Node 峰值 RSS/heap 约 544/341 MiB，数据库文件大小增加约 19.9 MB；输入小、无大 PDF，数字不是生产并发或大文件容量保证。测试结束按 owner 清理并核对 jobs/people/records/files/embeddings 均为零。首跑失败是测试把文件回执的额外字段传进严格 batch schema，纠正测试为 `file_id`/`sha256` 后重跑；没有放宽服务契约或隐藏失败（`distinct-scale.log`）。

此前的 10,000 条规模是**同一候选人**的沟通记录持久化，不是 10,000 位候选人的端到端结果。本轮只覆盖 500 位不同候选人、25 个很小的附件及受控向量；大规模真实原件、不同模型负载、实际生产并发、真实用户库索引和真实 embedding 成本仍未核验。
