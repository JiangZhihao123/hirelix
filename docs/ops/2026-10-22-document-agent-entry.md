# 推荐稿页面复用 Agent：最新资料改稿

## 真实发现

浏览器在现有内部推荐稿上提出“使用最新保存的筛选通话记录更新推荐”。新的通话已经经真实 Agent 保存，但页面入口直接创建独立 `revision`，只给改写模型原文及原始来源快照；模型无法检索新记录。旧路径保存到 v4，错误写出“最新记录没有提供业绩数字”。这是工程没有提供可检索执行能力，不是为特定候选人调整判断规则的问题。

本轮使用虚构 Cedarline/Avery 资料、真实模型与 worker、本机 Chrome Computer Use，以及本地隔离 PostgreSQL `hirelix_workspace_qa_local_20261022`。未重启或清空数据库，未推送、部署、外发或付款，未替用户选择 Owen 纠错。

## 修改

- 页面委托改为通过现有 `sendMessage` 创建普通 Agent 对话和工作。用户填写的原始请求、当前文档、职位、语言和时区进入相同 runtime；Agent 自行决定检索、精确修改、广泛改写或追问，不另建 Agent 或固定业务步骤。
- 独立改写服务保留为 Agent 可选择的写作工具和明确来源快照的修订能力。没有把所有资料自动加入文档，没有用关键词识别“最新”并硬写场景分支。
- 页面继续显示真实进度、停止、失败重试和对应对话入口。结束后读取当前保存文档；刷新可找回工作及对话。完成状态只提示“助理已回复”，不把一次回答或追问冒充改稿完成。
- 查找原页最近工作时忽略受父 chat 管理的子 revision，避免子任务遮住完整执行、对话入口和停止控制。
- 页面发起请求携带所见的文档版本。服务在创建任何对话或任务前，校验归属并锁定比较版本；旧页面与跨用户引用被拒绝。重试相同提交时复用请求 key。
- 刷新完成文档前尊重本地未保存编辑状态。失败与停止不声称已完成修改被回滚。

3. 新对话 `0c28f187-90e2-4ddf-9e98-f3dd1d0f3866`、父任务 `8ffd4e81-83c1-4db2-97ad-36522d58c9fa` 实际完成。其本次自主选择是读取文档、职位、检索人选，再改写同一稿件；不将该工具顺序设成未来验收条件。
4. 原稿 `dbd18b0d-f090-4154-a906-633d8419314f` 到 v5，实际包含三个新数字及自述/未验证边界，保留新客户优先级、薪资、通知期和许可未确认状态。
5. 页面自动显示更新后的正文；刷新后仍可进入对应对话，完整回复与保存结果一致。实际下载的 v5 PDF 文本包含新增数字及归属限定。此处仅核对内容，不宣称本轮改善了篇幅或排版。
