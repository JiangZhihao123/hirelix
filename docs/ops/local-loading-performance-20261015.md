# 本地页面加载优化验收（2026-10-15）

## 修改

- 订阅页与侧栏复用 BillingProvider；设置接口不再重复计算计费，打开订阅页不请求账户设置。
- BillingProvider 依赖稳定 user id，切换路由不重新加载；合并并发请求，短时间 focus/visibility 事件去重。保留可见页面 30 秒刷新和业务变化强制刷新；请求期间发生业务变化会补读。
- 账户页首次按需加载，同一设置页内切换复用结果；结账返回只刷新共享计费数据。
- Agent 订阅和试用不查询旧版 searches、usage_events、redemptions；原有 legacy 分支未在本次删除。真实本地 PostgreSQL 回归通过独占锁住这三张表验证 Agent summary 不依赖它们。
- 已付款周期与订阅状态合并读取，额度查询从三轮降为两轮；summary 基础设置与额度并行读取。无服务端额度缓存，扣费判断保持实时。
- 开发模式热更新复用数据库连接池，默认空闲连接保留 300 秒；生产默认仍为 30 秒。
- 本机 `.env.local` 改为 SSH 隧道访问同一个数据库，凭据未更改、未提交。未修改生产配置或部署。

## 连接

启动隧道（保持终端运行）：

```sh
npm run db:tunnel
```

本地 DATABASE_URL 使用原账号及库名，地址改为 `127.0.0.1:15432`，`sslmode=disable`。远程链路由 SSH 加密，PostgreSQL 仍只在 VPS 回环地址接受隧道转发；无需新增公网开放规则。隧道退出后重新运行此命令。更换 DATABASE_URL 后重启开发服务。

## 测量

使用用户现有 Chrome 登录态，真实 localhost 服务连接原数据库；没有替换接口或模拟订阅数据。修改前数据来自本轮前的开发服务器日志；并非受控相同网络环境下的基准测试。

| 指标 | 修改前观察 | 修改后观察 |
|---|---|---|
| 简单 SQL 热连接 | 509 / 1011 ms | 229 / 225 / 231 ms（隧道初测） |
| Billing API | 通常 3–7 秒，曾达 27.4 秒 | 最终连续刷新 1899 / 1979 ms |
| 刷新到订阅内容可见 | 未记录精确 DOM 时间 | 3122 / 3147 ms |
| 初次订阅页请求 | settings 与 billing 各计算计费 | billing 一次，无 settings 请求 |
| 账户/订阅来回切换两轮 | 重复数据路径 | settings 一次，billing 没有因切换增加 |

最终两轮认证 API 1002 / 983 ms，语言接口 1457 / 1453 ms，对话列表 1437 / 1576 ms。页面显示 Hirelix Pro、剩余 2994.37 额度及正确订阅周期。

中途曾观察到一次 billing 6 秒、数据到齐 8.6 秒，海外链路仍有波动；最终样本不代表延迟上限或生产 SLA。没有通过跳过认证或缓存扣费结果缩短时间。最终构建后重启开发服务，冷启动日志记录认证 3.4 秒、计费 3.0 秒，真实页面正常显示；因此上述约 3.1 秒是连接已建立后的刷新结果，不是服务重启后的首次加载承诺。
