# Agent Gmail 发送与真实验收

日期：2026-10-10。在独立工作区开发并合入本地 `main`，保留并整合同期的候选人维护和成果导出改动。尚未推送或部署生产。

## 用户行为

- 对话可查询当前 Gmail 发信授权；已知授权拒绝后提示重新连接，不把数据库中残留的 token 当成可用授权。
- 普通邮件可在对话中准备主题、正文和一个明确收件人；已关联推荐文档使用原文及已选附件。
- 首次请求总是展示收件人、发件人、主题、完整正文和附件。用户可通过确认按钮或明确的自然语言确认发送；修改后生成新预览，旧预览失效。
- 可在对话卡片取消。改问其他工作后旧发送预览失效，不建立独立审批中心或待办队列。
- Gmail 的成功、明确拒绝和不确定结果在原对话显示。发送与重复确认复用不可变发送回执；未知结果不自动重发。

## 实现边界

`conversation-email.ts` 处理对话预览和发送意图，复用 `gmail.ts` 的 MIME、附件读取、Google token、发送回执及去重逻辑。外发前重新校验用户归属、最新用户消息、任务租约、预览状态、文档版本、内容和附件哈希。停止/取消与发送保留有明确提交边界；已经提交给 Gmail 的邮件不能撤回。

普通邮件复用 `hirelix_private_email_deliveries`，只增加允许空的文档关联，不新建邮件业务表。待确认快照保存在所属 assistant 消息 metadata。迁移：`20261010_conversation_email.sql`。

重新打开对话时从持久回执恢复发送状态，即使发送成功后 worker 在保存回答前中断，也不再发送。推荐文档交付记录可从已成功回执恢复。

首版每封邮件一个收件人；普通邮件无附件，文档邮件使用已保存文档选定的附件。没有实现任意新增附件、CC/BCC 或自动定期发信。

## 验证

- 合入后的单元回归：355 通过、2 项原有跳过。
- 隔离 PostgreSQL 回归：8 项通过。覆盖并发去重、未知结果、停止 guard、用户隔离、文档更改、取消/过期预览、回执恢复、授权拒绝和已发送文档状态恢复。部分状态由测试明确写入，用于验证恢复分支，不作为真实 Gmail 发送证据。
- 真实 DeepSeek 意图回归：5 项通过，覆盖中文确认、更改收件人、取消、引用内容中的发送指令不执行、连接查询。
- TypeScript、ESLint、生产构建通过。构建使用 webpack；独立工作树的共享 node_modules 符号链接超出 Turbopack 文件系统根范围。现有两个路由的辅助函数导出导致 Next 构建失败，已单独移动到 lib，保持行为并通过原回归。

## 本地真实链路

Chrome → `localhost:3218` → 独立 QA PostgreSQL → 独立 worker → 真实模型 → Gmail API → Gmail 收件箱独立回读。

QA 库只从既有本地 QA 复制 schema 和测试账号登录记录，未复制生产候选人或职位资料。旧 QA Gmail grant 被 Google 拒绝，真实失败如实保留；随后只刷新到同一账号当日已验证的有效授权，未修改生产账号或配置。

1. Agent 查询连接，正确返回发件账号。
2. 请求普通邮件后展示预览；确认前零发送记录。
3. 更改收件人后旧预览失效，主题和正文保持不变。
4. 中文自然语言确认后 Gmail 真实发送成功，独立邮箱读取确认主题、正文、收件人和 SENT/INBOX；重复确认后成功发送仍只有一条。
5. 对保存的 QA 文档展示主题、正文与 `hirelix-gmail-qa.txt`，通过对话确认按钮发送成功；独立邮箱读取确认附件为 81 字节，内容与原文件一致。
6. 最终合入代码重新生成相同文档预览并确认：复用原 Gmail 回执，仍只有一封实际邮件；文档交付记录恢复为 submitted、版本 2。

仅发送两封到账号所有者本人邮箱别名的测试邮件，不含真实候选人资料。上述是本地真实服务链路；不是生产部署完成或新账号 OAuth 注册的证明。生产仍需应用迁移、部署前端/API 和独立 worker，并在生产复验。
