# 推荐交付本地验收 · 2026-10-15

## 实现范围

复用已有推荐文档、版本快照、分享链接、候选人反馈、Gmail 和发信记录；没有新增业务表或迁移。

- 默认生成推荐报告，客户网页按候选人组织理由、待核实事项、各自的原始简历和反馈。未结构化的旧内容完整展示，不按人名猜测归属。
- Gmail 和手动复制均支持可编辑主题、正文、推荐链接；带链接时默认短说明。服务端追加真实链接，拒绝未解析的模板变量。
- 直接发信可选择附上选定简历或仅发链接；Agent 邮件预览复用相同正文、链接和附件校验。
- 内部页面和客户页面均可下载 ZIP，包含推荐 PDF 和选定原始简历。复用权限、版本、文件哈希、分享撤销校验。
- 交付页面可直接发起 Gmail 授权，代码保存当前邮件草稿，回跳同一推荐页后恢复。连接不等于发送。
- 复制、下载和生成链接不标记为已推荐。实际发送成功或用户明确记录外部发送后才记录交付。

## 本地真实链路

使用隔离的本地 PostgreSQL QA 数据库、真实模型、独立 worker 和 Chrome；资料均为明确标注的虚构测试候选人。

1. 真实生成同一产品总监职位的三人推荐，并发布客户网页。Chrome 检查逐人理由、简历、共同补充说明的归属。
2. 在客户网页提交 Mira 的虚构反馈，页面显示成功；独立查询 PostgreSQL 验证反馈内容及候选人、职位关联。
3. Chrome 下载真实 ZIP，解包得到推荐 PDF 和三份原始简历；三份 CV 的字节哈希与数据库一致。
4. 修改邮件短正文并复制，读取系统剪贴板，确认正文和实际推荐 URL 一致。
5. 通过真实 Agent 请求“简短邮件 + 当前已发布链接 + 三份简历，只预览不发送”。首次发现模型保留链接占位符，修复校验和工具指引后以相同请求新开对话复测。
6. 最终真实邮件卡片含指定收件人、短正文、实际推荐链接、三份简历。数据库状态为 `review`，正文无 `{{` 占位符，该文档实际发信记录为 0。
