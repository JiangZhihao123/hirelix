# 改稿采用的来源与版本可核对

## 主流程缺口

新通话和客户反馈可以通过 Agent 进入推荐正文，但改稿工具没有选择并保存新来源的参数。文档来源仍列最初材料，后续核对只能打开当前记录，无法直接看见当时采用的原文。

## 实现

- 精确修改与广泛改写均可显式选择已观察到版本的职位和笔记。服务按用户、职位、人选与报告周期校验，读取真实来源后合入文档快照；不接受模型自行拼接的原文，不自动加入所有资料。
- 准备新文档与修订文档复用同一笔记选择服务，避免两套归属与周期规则。
- 广泛改写使用本次选择后的快照生成，保存正文、来源快照和关联记录 ID；排队后笔记发生变化，不会偷偷替换本轮选定的内容。改稿重复请求会比较来源选择，防止同一 key 复用到另一组来源。
- 来源相同且正文未变时不新增版本。新来源可以随一次正文不变的精确修改补入；不会据笔记文字擅自更新候选人档案或分享许可。
- 文档来源显示记录版本。点击先打开随该文档保存的原文，再提供“打开当前记录”的独立入口，区分当时材料与后来可能更正过的记录。
- 旧文档版本及原有来源保持原样，不追溯伪造旧版本使用过新增材料。沿用既有 JSON 快照与版本历史，没有增加业务实体、资料库服务或固定工作流。
