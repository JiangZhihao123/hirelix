# JD 收件授权与执行范围修复验收

日期：2026-10-19（Asia/Shanghai）。仅本地修改、测试与提交，不推送、不部署。

## 修复

- 通用 runtime 区分提供资料、分析请求和执行委托。只交来资料时简要理解并建议处理，不自动保存、查全库或研究市场；明确委托或接受具体建议后直接完成授权工作。
- 原工具只验证授权引文在用户消息中出现，不能证明其含义授权了该操作。内部写入现在复用现有结构化模型调用，结合拟执行动作、用户消息和助手提议上下文校验语义范围；排除排队、移除和晚于本轮请求的消息。没有授权则在事务写入前拒绝；前文有效授权、用户补充事实和简短接受仍可继续，撤回后不能再保存。
- 写入语义判断复用现有模型、用量记录和计费上下文，无新增依赖、业务实体或工作流。代价是每次内部写入多一次模型判断；它不是权限、用户隔离或外发确认服务的替代。
- 工具失败后先判断该操作是否必要且有授权，只在新证据或有效参数能解决错误时重试。市场调研与助理建议不作为客户反馈写回职位要求，保留原有反馈来源校验。
- 保存职位保留完整客户名及 JD；薪酬和工作条件同时进入匹配标准。Skill 补充接收资料、客户要求与专业判断的边界；没有针对测试公司、岗位或措辞的代码分支。
- 将界面语言上下文从 `preferred_language` 更正为 `ui_language`，明确按用户自己的说明语言回答，不按嵌入英文 JD 的语言回答。
