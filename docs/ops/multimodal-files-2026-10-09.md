# 多格式附件读取与视觉对话

2026-10-09，按用户批准的按文件类型处理方案实施。

## 文件进入 Agent 的方式

- JPG/JPEG、PNG、WebP：解码校验、纠正方向、限制分辨率；视觉模型读取原图。文字转录用于事实核对，最终回答仍接收图像内容。
- PDF：官方 PDF.js 提取各页文字并渲染完整页面，文字与页面图像共同供最终模型读取。扫描页补充视觉转录，候选人整理也接收页面图像。
- DOCX：Mammoth 读取正文；包含的受支持图片作为独立媒体附带，标明媒体顺序不是页面顺序。
- XLSX：ExcelJS 读取所有工作表及非空单元格，保留工作表名和单元格地址。公式使用文件保存的结果，不执行公式、宏或外部连接。
- PPTX：读取 OOXML 幻灯片文字和受支持的内嵌图片；不宣称完整幻灯片版式渲染。
- CSV、TSV、TXT、Markdown、JSON、HTML、XML：严格 UTF-8 读取。源文件内容始终是证据，不是对 Agent 的授权或指令。

最初使用既有 OpenRouter 连接调用 `qwen/qwen3-vl-32b-instruct`。该模型于 2026-10-09 被提供方下线，2026-10-10 的真实简历请求返回 404。现已复用统一 LLM 客户端，官方 DeepSeek 配置下由 V4.1 Flash（`deepseek-flash`）直接读取原图和 PDF 页面，结构化读取使用官方 JSON 模式。视觉调用按真实图文 token 用量及官方费率结算，保留原有额度预留和私密请求内容脱敏；不把 OCR 转录当作图片的唯一信息通道。详见 [简历完整链路修复与验收](candidate-intake-2026-10-10.md)。此前硅基流动现有凭据的真实视觉测试返回 402，未将该失败记为成功。

原文件继续保存在按用户隔离的现有 PostgreSQL 文件表，不新增存储服务或迁移。后续追问复用同一批附件，分析请求不擅自建档；用户明确要求保存候选人时复用现有导入、身份冲突与事务机制。

PDF.js 固定为 `5.4.624`，Canvas 固定为 `0.1.100`，与当前 CI/VPS 的 Node 20 兼容。使用 PDF.js 自己的 CanvasFactory，避免不同版本原生 Path2D/Canvas 对象混用；兼容版本的扫描 PDF 已重新进行真实视觉验证。

Vercel 的文件追踪须显式包含 Sharp 动态加载的 libvips 共享库。首次正式站验收发现共享库遗漏导致接口 500；不能以构建通过替代部署后的附件和对话验收。

## 可维护的处理边界

每个原文件仍不超过 4 MB（匹配现有 Vercel 上传限制）；每条消息最多 20 张图像/页面，视觉请求不超过 24 MB。解码限制 1600 万像素，模型图像最长边最多 2048 像素；Office 文件解压限制 30 MB；Excel 最多 20,000 个非空单元格。超过限制明确报错，不默默遗漏剩余页或行。

旧版 DOC/XLS/PPT、音视频、压缩包和任意二进制文件不在本次支持列表中。图片转录和视觉判断仍可能出错；无可读内容、损坏文件及服务失败均明确反馈，不伪装为已读。

## 附件体验复查与修复

首次验收验证了回答正确，但没有完整覆盖用户操作；2026-10-09 再次按桌面浏览器操作发现并修复：

- 上传前没有图片缩略图；发送后仅显示文件名。增加本地缩略图及消息内图片入口，临时 URL 在组件退出时释放。
- 消息里的文件会直接下载，回答里的来源却显示文字转录，用户看不到原图。两个入口统一打开当前对话的来源面板；图片显示原图、PDF 使用浏览器原生查看器，其他文件显示确定性提取的文字，下载另设入口。
- 预览接口重新调用视觉模型。改为不调用模型的只读预览，不重复 OCR 或视觉读取；只有执行 Agent 请求才读取视觉内容。
- 附件发送过程中没有即时用户消息，只剩等待状态。消息和附件立即出现在对话中；上传阶段只显示一条真实上传状态。
- 不支持/超限文件仍能点击发送，随后报错。现在文件卡片直接解释并禁用发送，移除后恢复。
- 一次失败同时被前端和 API 用作整段对话的锁。允许发更正消息；保留运行中的互斥和失败回执，并拒绝从旧标签页重试已被新消息替代的请求。
- 附件全部不可读仍进入模型规划。当前消息全部附件读取失败时直接说明更换文件或继续发新消息，不把无内容任务送给模型猜测。

验证记录：本地真实 Chrome 已验证原图预览和损坏附件的明确失败；真实 PostgreSQL 回归验证更正消息入队、运行中互斥、旧失败任务不可重跑以及最新失败任务仍可重试。单元测试 348 通过、2 跳过。浏览器截图和恢复记录与上述证据同目录；部署后验收另外记录，不以这些本地证据推断生产通过。
