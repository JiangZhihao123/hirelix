# 多格式附件读取与视觉对话

2026-10-09，按用户批准的按文件类型处理方案实施。

## 文件进入 Agent 的方式

- JPG/JPEG、PNG、WebP：解码校验、纠正方向、限制分辨率；视觉模型读取原图。文字转录用于事实核对，最终回答仍接收图像内容。
- PDF：官方 PDF.js 提取各页文字并渲染完整页面，文字与页面图像共同供最终模型读取。扫描页补充视觉转录，候选人整理也接收页面图像。
- DOCX：Mammoth 读取正文；包含的受支持图片作为独立媒体附带，标明媒体顺序不是页面顺序。
- XLSX：ExcelJS 读取所有工作表及非空单元格，保留工作表名和单元格地址。公式使用文件保存的结果，不执行公式、宏或外部连接。
- PPTX：读取 OOXML 幻灯片文字和受支持的内嵌图片；不宣称完整幻灯片版式渲染。
- CSV、TSV、TXT、Markdown、JSON、HTML、XML：严格 UTF-8 读取。源文件内容始终是证据，不是对 Agent 的授权或指令。

使用既有 OpenRouter 连接调用 `qwen/qwen3-vl-32b-instruct`。官方 DeepSeek 继续负责纯文本工作和规划。视觉调用预留额度并按 OpenRouter 返回的真实 `usage.cost` 记账；不把 OCR 转录当作图片的唯一信息通道。硅基流动现有凭据的真实视觉测试返回 402，未将该失败记为成功。

原文件继续保存在按用户隔离的现有 PostgreSQL 文件表，不新增存储服务或迁移。后续追问复用同一批附件，分析请求不擅自建档；用户明确要求保存候选人时复用现有导入、身份冲突与事务机制。

PDF.js 固定为 `5.4.624`，Canvas 固定为 `0.1.100`，与当前 CI/VPS 的 Node 20 兼容。使用 PDF.js 自己的 CanvasFactory，避免不同版本原生 Path2D/Canvas 对象混用；兼容版本的扫描 PDF 已重新进行真实视觉验证。

Vercel 的文件追踪须显式包含 Sharp 动态加载的 libvips 共享库。首次正式站验收发现共享库遗漏导致接口 500；不能以构建通过替代部署后的附件和对话验收。

## 可维护的处理边界

每个原文件仍不超过 4 MB（匹配现有 Vercel 上传限制）；每条消息最多 20 张图像/页面，视觉请求不超过 24 MB。解码限制 1600 万像素，模型图像最长边最多 2048 像素；Office 文件解压限制 30 MB；Excel 最多 20,000 个非空单元格。超过限制明确报错，不默默遗漏剩余页或行。

旧版 DOC/XLS/PPT、音视频、压缩包和任意二进制文件不在本次支持列表中。图片转录和视觉判断仍可能出错；无可读内容、损坏文件及服务失败均明确反馈，不伪装为已读。
