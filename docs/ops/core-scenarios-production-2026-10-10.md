# 八个核心场景的生产基础链路验收

2026-10-10。环境为 `hirelix.online`、真实 Chrome、官方 DeepSeek、生产 PostgreSQL 与 `hirelix-scheduler`。使用虚构客户 Fictional Meridian Pilot 1010、候选人 Tessa Reed Core Pilot 1010 和两份明确标记的 QA 文本文件；未使用 mock 服务替代真实结果。

本记录验证八个场景串成同一条工作链，包含跨对话续接、保存后独立数据库读回、文件实际下载和渲染。它不把基础用例通过等同全部输入、全部账户或完整商业发布验收。

## 场景与证据

| 场景 | 实际操作与验收结果 |
| --- | --- |
| 1 接下招聘需求 | 从对话上传 JD 并明确授权保存。一份职位，保留原始 JD、原附件和来源详情，未混入后来反馈。首轮供应商格式故障修复后，原对话原任务重试成功。 |
| 2 积累和理解候选人 | 同一对话上传简历并授权整理。一份候选人，CV 来源可打开；未编造薪资、离职期、兴趣或分享许可，私人测试笔记保留为内部资料。 |
| 3 从已有资源匹配 | 新建第二段对话，不重传文件，检索已保存职位和候选人。回答使用 4 位 PM、企业 onboarding、首次有效 dashboard 从 15 天降至 7 天等来源事实，区分策略范围未证实。仅分析，没有新增业务记录。 |
| 4 准备沟通 | 基于职位和履历提出重点问题；接收用户供应的电话事实，真实保存沟通笔记及 Interested 关系状态。确认能周二/周四到办公室，不推断未问的薪资、离职期和分享决定。 |
| 5 向客户推荐 | 创建推荐并从对话继续修改同一文档，保存到第 2 版，113 个英文单词。原生下载 PDF 和 DOCX，实际文件内容与已保存正文一致；均为一页，已渲染查看，无截断、重叠，均排除内部标记。没有发给客户。 |
| 6 推进反馈 | 保存客户反馈，将当前办公室要求改成仅周二，职位变为第 2 版；原 JD 仍保留周二/周四，两份历史来源不同。团队管理、产品与 onboarding 条件保留；生成后续策略范围问题，旧推荐不被分析请求自动改写。 |
| 7 跟进约定 | 对话保存明确时间的一次提醒，在真实到期时回到原对话：到期 11:45:08.524 UTC，完成 11:45:09.086 UTC。数据库确认一条提醒消息、一条通知。另保存每周一 09:00 UTC 的变化后才通知约定，随后原生暂停；暂停状态与数据库一致。 |
| 8 回顾与下一步 | 回顾当前职位、候选人、反馈、推荐、提醒及已暂停约定。明确当前只需周二、策略/薪资/离职期仍待问、推荐已准备但从未发出。给出三个具体下一步；metadata 的 actions/work/reminders/schedules 都为空，未新增或修改业务资料。 |

独立读回：本 QA 客户下职位 1、候选人 1、关系 1、推荐 1；职位版本 2、候选人版本 1、推荐版本 2。分享许可先保持 unknown，随后明确报告拒绝才转为 declined；兴趣保留 Interested。周期约定最终 enabled=false，一次提醒 completed 且 enabled=false。此 QA 推荐的邮件发送回执为 0。

PDF/Word 是通过真实浏览器点击后落盘；浏览器插件未捕获 blob 下载事件，以下载目录文件、文本比对及渲染图作为下载证据，没有把按钮存在当作下载完成。

## 本轮发现与根因修复

- `799001b`：供应商完整答案里的未转义控制字符触发增量提取器 JSON.parse，提前中断了本应继续的结构校验和修复。预览解析失败现在不破坏完整传输，最终 JSON 仍必须通过校验；原失败任务在生产原地重试成功。
- `b2f0ed0`：下一条请求提交期间仍拿着上一轮 completed job，短暂重复显示旧正文。提交期间只显示本次 pending 状态；真实 Chrome 下一次发送已确认没有旧回复重复。
- `058db95`：模型把“尚未取得分享许可”误判成“拒绝”，生成了未应用的拒绝建议。规划、回复和授权恢复共同使用 absence/unknown/granted/declined 规则；真实模型与生产复测中没有新拒绝建议，数据库仍 unknown。原错误建议未点击应用，未删除历史失败证据。另补充显式预览必须返回真实动作。
- `ca516d5`：长回复进入格式修复时清空/重启预览。首轮非空正文保留至最终有效消息保存，格式修复不再向 UI 推送空串或替代片段；失败和取消仍标为未完成。真实模型/PG 回归验证增量、持续预览、最后原子保存、取消后的迟到写入与重复停止去重。

明确拒绝分享之后，生产实际请求准备同一份推荐邮件，Agent 返回不可发送/分享的原因，没有确认发送卡。没有点击发送、没有邮件提供方投递、没有公开发布链接；数据库回执仍为 0。

## 验证边界

- 资料验收为虚构 JD/CV 文本与一个具体匹配组合，不代表任意简历格式、OCR、大候选人库召回质量或所有语义判断均已通过。
- 一次提醒实际自然投递；每周约定本轮只验证保存、下一次时间与暂停，没有等待下周一生产周期生成。既有本地真实调度回归是另一层证据。
- 当前已有登录态的真实 Chrome 已通过；本轮没有重做新用户 Google OAuth、扩展 Gmail 授权、实际外发、支付或公开分享。不能把邮件阻断正确推断成所有 Gmail 投递场景通过。
- 核心链路与交互已验证的具体范围见上表；全部网络故障、所有并发恢复、OpenRouter 非流式备用输出不计入本轮通过范围。
