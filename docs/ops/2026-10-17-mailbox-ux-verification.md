# 邮箱连接与发件人体验验收（2026-10-17）

## 改动

- 设置独立为 Account / Email / Subscription and usage。已连接邮箱展示真实地址及发送、读取可用状态；默认发件人与断开操作收在管理中。
- 发送授权与可选读取授权分开。读取未开放时，连接入口不主动请求读取权限；已有可用读取权限在重连时保留。断开前说明影响，保留既有业务历史。
- 对话连接卡片只展示相关邮箱的实时状态，可展开其他邮箱，不再嵌套整套设置。
- 默认发件人保存在现有用户设置表，Agent 与推荐邮件共享。已有邮件预览或单封邮件选择优先，不静默更换发件人。
- 推荐邮件草稿按用户、文档、版本隔离，保留在当前标签页的 sessionStorage；刷新及同标签页 OAuth 跳转恢复渠道、发件人、收件人、正文、主题、链接与附件选择。关闭标签页后不承诺恢复。
- OAuth 返回恢复请求由实际点击生成的本地标记触发，绑定用户、对话、源消息及幂等键。服务器拒绝已经出现后续消息的旧请求。恢复执行仅允许读取已有业务上下文与准备邮件预览，禁止发送、发布、创建委托及业务变更。
- 保存最近核实的邮箱地址。网络错误显示检查/重试，明确权限失效显示重连，加载中不显示未连接。

## 本地真实验证

环境：localhost:3000，隔离 PostgreSQL `hirelix_workspace_qa_queue_20261015`，真实 Chrome 登录态、独立 Agent worker、真实 Google / Microsoft 账号身份与 DeepSeek。

- Chrome 设置页将 Outlook 设为默认，刷新后仍保留；推荐页面自动选择 Outlook。单封改选 Gmail 后默认仍为 Outlook。
- Chrome 修改主题、正文、收件人，取消简历附件，刷新：Email 标签、Gmail 发件人及所有编辑值恢复。截图：`tmp/mailbox-ux-after/draft-restored.png`。
- Chrome 展开断开说明后取消：邮箱仍连接。对话紧凑卡片展开其他账号成功，只有一个标题。截图：`tmp/mailbox-ux-after/conversation.png`。
- 服务器真实续准备请求验证：重复请求返回同一 job，旧源消息的新恢复请求被拒绝；真实 worker 使用默认 Microsoft 邮箱生成 `review` 预览，主题和正文准确，未发送。
- 首次真实执行遇到 DeepSeek 连接超时；直连恢复后，从 Chrome 原任务 Retry，最终完成。未用模拟模型代替。
- 发送记录验收前后均为 5 条，没有新增发送记录。临时对话、消息、job、通知已按本次 ID 清理；测试设置的默认发件人恢复为原先未设置状态。
- 类型检查、修改文件 ESLint 通过。单元测试 464 项：456 通过，8 跳过，0 失败。新增恢复工具权限约束测试。

## Google 验证警告与边界

在真实 Chrome 只读查看 Hirelix Production 项目（`loyal-glass-510417-t9`）：客户端列表与此前产生警告的 OAuth 客户端相符；Data access 显示 `gmail.send` 已验证、`gmail.readonly` 未验证。先前发送按钮携带读取范围是触发未经验证流程的原因。没有修改 Google 控制台配置或绕过警告。

本轮没有重新完成外部 OAuth 授权，也没有授予新读取权限或发送验收邮件。实际验证覆盖已连接账号、默认偏好、草稿刷新、恢复请求的服务器/真实 Agent 链路；新授权成功/取消到前端自动恢复的完整浏览器回跳仍需后续授权验收。Google 读取审核并未完成，不能将本次 UI 改造视为审核通过。
