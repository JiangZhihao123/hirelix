## 如何核对，而不是只看最终回答

QA 入口 `scripts/qa/run-observed-workspace-worker.ts` 仅在指定本地 QA 库和证据目录下运行。它透明转发原有 fetch，不替换依赖、不制造响应：

- 记录实际发送的 DeepSeek JSON 请求体、真实 Search/Fetch 响应及状态。模型流不被重新生成或替换。
- 不记录请求头、API key 或 Authorization。证据只有本轮公开页面与虚构业务资料，存于本地归档，未提交 Git。
- 用当前消息创建时间和原文关联模型请求，避免同一句任务重复运行时串到另一个用户/对象的轨迹。
- 对照供应商原始结果和后续模型 tool 消息：URL 归一化、摘要/正文前缀、相关度、权威度、日期、全文或截断标记一致；错误明确保留 HTTP 状态。
- 对照模型看到的私有对象与 PostgreSQL：引用 ID、JD、候选人笔记、profile、文本附件原文正确；已提交 record 回执指向同一用户的持久记录。
- 对照真实有效响应和账本 `private_web_*` 快照。七笔有效 Search 加一笔有效 Fetch，共八笔有效请求；另一次空 Search 和一次 Fetch 404 均不计有效请求费。模型自身调用仍独立按 token 记账。
- 完成任务的工具卡片均为 done/error，没有遗留 running；分析没有被工程自动转换为业务写入。是否发送任何特定工具请求由 LLM 决定。

本轮回读的是这次执行时真实传给模型的数据，不要求产品永久保存每个网页，也没有新增网页快照服务或固定研究工作流。
