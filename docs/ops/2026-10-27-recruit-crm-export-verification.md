## 当时的实现与验证（不代表当前实现）

- 修复重复表头拒绝或覆盖的问题，保留每个原始表头及列位置；限制邮箱和个人资料 URL 映射为单列，分别拆分多列技能。将实际字段拼接行为与允许的列键传递给模型，并约束结构化输出只能引用真实列。此前真实模型曾把全名和名、姓重复拼接；修复后真实模型与 PostgreSQL 对脱敏平台结构样本完成正确导入。
- 可在一次委托中提交名单和相关附件 ZIP，顺序不限。仅当平台候选人资源 URL 与附件目录 ID 明确一致，且在当前用户库中只对应一人时，才关联原件；匹配不到、多重身份和其他对象文件保留在原 ZIP 内并在对话中列出。导出文件没有扩展名时只依据 PDF 文件签名识别类型，保留原名和原始字节。
- 自动关联的文件先作为附件，而非直接断言是简历或赋予分享权限。用户或 Agent 明确识别为简历后，可注册为 CV；推荐源选择、打包、共享下载和邮件附件均接受已验证的无扩展名 PDF，并在对外交付文件名添加 `.pdf`，私人原件名不变。未提取到文本的附件也保留并提示。
- Agent 可按路径读取 ZIP 内文件、分页读取长文本，并在保存历史记录时将具体源文件和 ZIP 路径一起保留。来源与记录日期不等于分享授权或候选人当前意愿。
- 本机隔离 PostgreSQL 的实际未修改平台 CSV/ZIP 验证了 ID 对应、PDF 原件逐字节一致和文本提取；该直接契约测试未把原始平台文件发送给模型。另用脱敏平台结构、真实模型和数据库验证一次导入、相反文件顺序、未匹配项、原件、事务回滚、重复导入、手工确认合并和用户隔离。
- 真实 Chrome、项目指定的本地 Google 登录及独立 worker 验证了一次自然对话：1 位候选人保存、1 个 PDF 关联，1 个候选人附件未匹配、1 个联系人文件未处理；候选人来源页展示 PDF 提取文本，Chrome 可直接打开无扩展名 PDF，真实 embedding 检索可找回该人及附件文本。该次没有创建职位或发送邮件。
- 一次模型答复把“目录有 ID，但没有找到对应候选人”说成了“路径没有 ID”；系统回执和界面显示的是正确原因。将其作为模型表现观察，不据此添加针对样本的业务分支，也不把模型文字当持久化回执。

本地测试记录位于同一私有验收目录，包含真实文件、自动回归日志及实际 Chrome 执行记录。代码的迁移文件只在本地隔离库应用，尚未 push 或部署。
