# 单职位、多候选人推荐与反馈验收

日期：2026-10-13。范围：本地真实链路，非生产发布验收。

## 实现

- 职位页可把当前候选人的评估和比较交给助理。Agent 使用 `save_assessments` 把获准保留的判断写入现有候选人—职位关系，保留证据版本与历史；不调用第二个模型重复评估，不改候选人事实资料。
- 评估按职位隔离；简历、当前职位资料、相关沟通或关系事实变化后提示重新判断。其他职位下的沟通不会影响本职位评估。
- 同一职位可选择多人及各自 CV，生成客户推荐页。与邮件格式区分，内部评估不会直接成为客户文案。
- Agent 通过 `share_document` 发布或撤销推荐链接。相同版本复用链接；编辑不改已发布副本，发布新版本替换旧链接。发布链接不等于发邮件或记录交付。
- 客户可分别表达希望面试、暂缓、本职位不再推进或补充意见。反馈关联推荐版本、职位和个人，保存为独立来源记录。提交姓名不作已验证身份。
- 反馈回到生成该推荐的原对话，职位页也展示每人的最新反馈。新会话可通过职位和推荐读回反馈。只在用户继续委托时做进一步 Agent 分析，不自动安排面试、修改 JD 或发送消息。
- 对话从现有侧栏轮询获知更新后刷新正文，保留输入草稿；内容到达页面后才按 PostgreSQL 完整时间精度标记相应通知已读，避免标记尚未加载的反馈。
- 沿用现有表、jobs 和 ReAct；没有新增业务工作流引擎、审批中心或数据库迁移。

## Chrome 实际验收

Next.js 在 `localhost:3000`，独立 scheduler 使用本轮代码，外部人才寻访调度关闭。数据库为本机隔离库 `hirelix_workspace_qa_react_week_20261011`。资料是明确标为 QA 的虚构职位及三位测试候选人；模型调用、PostgreSQL、任务执行、文件下载和浏览器交互都是真实链路，没有用 mock 代替服务。

1. 从职位页点击“评估候选人并汇报”，发送预填指令。Agent 读取本职位及三人的资料，保存三份职位评估，汇报主选、备选和证据差异。
2. 在对话选择 Alice 和 Ben，暂缓 Cara；授权制作中文客户推荐页、使用两人的筛选记录与 CV，明确不发送邮件。生成同一份包含两人的推荐及两份 CV。
3. 该测试账号原有 AI 额度耗尽，首次执行在保存推荐后中断。仅给隔离测试库中的该账号设置本地 QA 额度，点页面“重试”；Agent 读取并复用已保存材料后发布，没有重复创建推荐。未改生产额度、支付或账单。
4. 从客户页面分别提交 Alice 希望面谈、Ben 暂缓，以及 Alice 的补充面谈关注点。浏览器显示反馈已发送；独立查询确认每条记录绑定正确的候选人、职位和推荐版本。
5. 新开该职位的对话，请助理汇报反馈及准备面谈问题。它读取职位、三条沟通记录及推荐，正确区分 Alice 希望面谈但日期未定、Ben 暂缓，准备了动手工程及绩效管理问题；未调用修改 JD、安排面试或发送工具。
6. 下载 Alice 的原 CV，实际文件 SHA-256 与数据库保存的 SHA-256 一致。
7. 指令在原推荐正文开头增加一句话并发布最新版。Agent 调用读取、原文编辑和分享工具，同一推荐升到版本 2，正文其余部分和两份 CV 保留；对话显示固定的“打开客户推荐页”入口。版本 1 的三条反馈仍存在。
8. 在版本 2 再提交一条 Alice 的意见。保持原对话打开、输入框留有未发送草稿：反馈自动出现，草稿未丢失；对应通知随后标为已读，Chrome 错误日志为空。

本轮最终数据：一个职位、三个关联候选人和三份评估、一个推荐的两个版本、两份 CV、四条反馈（版本 1 三条、版本 2 一条）、一个有效分享链接。推荐的 `submitted_at` 为空；没有发送邮件或虚构完成面试。
