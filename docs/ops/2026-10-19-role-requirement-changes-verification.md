# 客户要求变更与重新匹配：本地验收

日期：2026-10-19（Asia/Shanghai）。仅本地修改、测试和提交，不推送、不部署。

## 发现与修复

1. **只改要求时工具先失败。** 原更新工具强制要求额外的标题、联系人、状态补丁，模型传 `changes: null` 时 schema 拒绝。现允许该补丁为空，按未变更处理，完整 brief 和来源要求仍保留。新反馈只收集实际使用的内容、日期和文件，不再要求无用途的类型和标题；未知日期/文件可省略，反馈不能凭空补造。
2. **新门槛未充分影响评估。** 放宽直属管理限制、改为项目协调经历后，模型曾将缺少新项目规模证据的人也标为值得讨论。对话匹配现复用既有 `ROLE_BRIEF_EVIDENCE_RULES`，并明确替代条件不能被一并取消；强制专业经历未证实的人保持需要更多信息，不凭头衔或其他优势补足。Skill 同步指导更新 priorities、flexible、unknowns，并重新考虑旧结论。
3. **复杂评估参数可能格式错误。** 补充空列表的契约说明，接入 AI SDK 官方 `experimental_repairToolCall`。优先无损解开重复 JSON 编码；必要时只尝试一次结构修复，仍通过原 schema。确定性检查禁止改变或新增事实标量、对象 ID、来源和授权引文；修复不了就保留错误，由 Agent 根据实际错误恢复，不绕过业务校验。trace 记录参数问题路径和修复结果，不记录敏感字段值。
4. **结构修复与主回复的额度预留冲突。** 补充测试触发了嵌套格式修复覆盖主回复预留，导致误报额度不足，实际并非总额度耗尽。结构修复按产品格式重试处理，单独记录服务商用量，由产品承担，不修改主回复的额度预留或消费记录；普通业务模型调用仍正常计费。

没有按公司名、岗位、候选人或数字写业务分支，没有新增业务实体、工作流或依赖。
