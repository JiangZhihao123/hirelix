# 冷启动能力：本地实现与验收

日期：2026-10-27。环境：本机隔离数据库 `hirelix_workspace_qa_coldstart_20261027`；Next.js 与独立 Agent worker 连接同一数据库。未 push、未部署、未在生产执行迁移；不构成生产放行或获客效果验证。

## 已实现

- 公开人选研究由 `public-sourcing` Skill 提供方法，Agent 自主调用现有搜索、抓取及业务工具。保留搜索摘要与页面正文的区别、来源、时间和未知事项。旧 Bright 及独立付费寻访路径没有重开。
- CSV、TSV、XLSX 逐行导入，逐工作表映射字段；仅向模型提供表头与样本，所有原始行由确定性解析处理，避免把整表当文档摘要而遗漏后续人选。原件、未知字段、表单行和工作表来源保留。授权明确的新候选人直接保存；已有身份和字段错误保留为明确待处理项。
- ZIP 可以同时携带候选人表和简历；保留原始 ZIP 和各文件，原子提交候选人变更。拒绝重名路径、不支持的文件和超限输入，不静默漏文件。它不是所有 ATS 多实体全量备份的恢复器。
- 会话附件上限 50 MB，超过 4 MB 时以 2 MB 分片上传；浏览器草稿保留同一上传 ID，重试查询已接收分片。最终校验长度和 SHA-256，完成回执可重试。临时分片不能作为业务原件读取，成功合并后移除；尚未完成的分片保留以便续传，不另加定时清理服务。
- 上传仍沿用现有私人文件表，增加两个分片字段及唯一约束，没有新增对象存储服务或通用任务引擎。分片针对 [Vercel 的 4.5 MB 单次请求限制](https://vercel.com/docs/functions/limitations)；本轮没有验收 Vercel 部署环境。
- 新用户可选择导入已有候选人、公开研究或比较候选人，均只填写可编辑委托。普通落地页与价格页入口不再强制预填保存简历；具体比较示例仍保留示例委托。FAQ、产品说明和 llms.txt 与此一致。

## 真实链路与数据库契约

证据目录：`/Users/noah/projects/hirelix-local-archive/2026-10-27/`。测试文件及角色均为合成材料，不包含厂商真实用户的导出备份。

| 验证 | 实际结果与边界 |
| --- | --- |
| 独立 worker + 真实模型 + 真实公开搜索 | 自然委托完成。模型自行读取寻访 Skill、执行 8 次搜索和 2 次抓取。80 条返回来源及摘要、时间信息进入后续模型请求；两次供应商抓取 404 作为错误进入模型观察。研究请求没有新增候选人、职位或发信。调用次数只是观察，不是测试规定的工作顺序。 |
| 抓取服务独立核对 | 同一真实 Fetch API 可读取示例站与官方文档；本次个人站点仍返回 404。不能把这个 404 断言为原站不存在或 LinkedIn 拦截。不能把供应商摘要当已读取原网页。 |
| 1,000 人、多工作表 XLSX | 真实模型字段映射、真实 PostgreSQL 保存 1,000 人及 1,000 份 profile 来源，保留未知导出列和原件，所有人的索引工作已入队。没有用模型输出上限裁掉第 101 人以后资料。 |
| 混合 ZIP 与后续授权 | CSV、TSV、简历文本合计 3 人；先形成资料，后续授权保存 2 位新候选人，1 位已有身份保持冲突。重复执行没有再新增；模拟事务失败后没有部分候选人写入。每行引用实际内嵌文件，原件逐字节一致。 |
| 原有 CSV / 文档回归 | 实际 DOCX/PDF 文本读取、空 PDF 明确拒绝；CSV 映射、显式合并、版本与原件保留、导出、幂等及会话上传归属，共 3 项原有集成测试通过。 |
| 分片服务与数据库 | 4.2 MB 中断状态恢复、并发重复分片、冲突内容、SHA 校验失败、完成回执重试、用户隔离、临时分片不可读取及成功清理通过。50 MB 上限用实际数据库组装和校验通过；该进程峰值 RSS 约 755 MiB，不代表生产容量或并发承载证明。100 MB 探测峰值超过 1 GiB，最终限制收敛为 50 MB。 |
| 真实 Chrome + Google OAuth + Agent | 使用项目指定账号登录本地隔离环境，从新用户入口自然交办混合 ZIP。3 位候选人保存，对话回执可展开人选和原始文件，无额外导入向导。另上传两个 6,484,894 字节 ZIP（含中文文件名），经真实分片 API 完成并入对话，数据库与本地 SHA 及逐字节一致。仅留附件的委托没有导入候选人或外发。 |
| 后续检索 | 实际 embedding 服务与数据库检索返回已导入的 3 人；覆盖计数为 total=3/indexed=3/pending=0/failed=0，可找回含 2021 年沟通信息的人选来源。相似度不是 JD 适合性结论。 |

工程回归：`npm run test:unit` 525 项中 506 通过、19 项按环境条件跳过；上述真实导入集成 5 项、分片集成 2 项另行执行并通过。真实 Chrome channel 的落地页与 SEO 17 项通过，包括无 JavaScript 入口及归因。`npx tsc --noEmit`、ESLint、`npm run build` 和 diff 空白检查通过。

模型表现另作观察：公开研究样本能够产出带来源的人选线索，但部分陈述仍依赖供应商摘要，不能据此承诺事实完整性、当前任职或适合性。混合 ZIP 已保存后，模型因合成资料又提出了一次额外处理选择；没有据此自动删除，也没有新增针对该样本的业务分支。这些不是工程验收对任意模型回答质量的保证。

## 仍需明确的范围

1. 单个表或 ZIP 最多 10,000 候选人；ZIP 最多 500 文件、合计 30 MB 解压量；每条消息最多 20 个附件。多实体导出中的公司、客户、独立 notes/associations 不会被承诺成已完成结构化迁移。
2. 首批来源优先级及各平台官方导出范围见 [平台调研](../product/candidate-import-sources-2026-10-27.md)。通用文件验证与官方格式说明，不等于已使用每家厂商真实账号完成整库导出、历史关联及附件迁移验收。
3. 部署这些改动前，需要先在目标数据库应用 `supabase/migrations/20261027_candidate_upload_parts.sql`，再发布应用/worker。该迁移只在本地隔离数据库执行；生产迁移及部署尚未授权或执行。
