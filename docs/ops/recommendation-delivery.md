# Candidate recommendation delivery

Recommendations expose three delivery options: a revocable client link, copied email text, and Gmail sending. Internal reviews cannot be published or emailed as client recommendations.

Apply `supabase/migrations/20261003_add_recommendation_delivery.sql` before deploying. Shares contain an immutable, allowlisted copy of the selected document version and the explicitly selected CV references. Draft edits do not change an existing client link. Publishing a newer version revokes the previous link. Links expire after 30 days; revocation also denies attachment downloads. Link signatures use the application `BETTER_AUTH_SECRET` with a dedicated purpose string. Rotating that secret invalidates existing client links. Public routes must remain no-store and noindex; do not log their bearer URLs.

Gmail reuses the existing better-auth Google account linking and callback. It incrementally requests only `https://www.googleapis.com/auth/gmail.send` in addition to Google sign-in scopes. Enable Gmail API in the Google Cloud project associated with `GOOGLE_CLIENT_ID`, add the sending scope to the OAuth consent configuration, and complete Google's sensitive-scope verification for public launch. The callback remains `/api/auth/callback/google` on each approved origin. Existing profile-only sign-in does not grant sending rights.

Sending is an explicit action on the reviewed recipient, subject, body and selected attachments. It does not read the inbox. The server binds every send to an owned document version, persists the reviewed copy, and guards concurrent/repeated sends by request key and content/attachments/recipient fingerprint. Gmail acceptance is recorded before updating workspace submission status. A network timeout or ambiguous server response is not automatically retried: the UI asks the user to check Gmail Sent. A stale sending record is shown as unconfirmed after two minutes. This intentionally favors avoiding duplicate emails over silent retries; no inbox-read permission is requested for automated reconciliation. A failed, definitively rejected send can be attempted again with a new request key.

Disconnect discards Google API credentials from the linked account while retaining its identity for normal sign-in. The user can also revoke Hirelix in Google Account permissions. Reconnecting requests consent and offline access again.

Acceptance boundary, 2026-10-03: local real AI produced a recommendation from the browser-imported fictional candidate. Anonymous link rendering, exact original attachment download, nonselected-file denial, version isolation, expiry/revocation, and email clipboard readback were verified. Gmail reached Google's "app not verified" screen. No Gmail grant or email send was performed. Do not describe Gmail as production-verified until OAuth verification/consent and an explicitly authorized real send with receipt have passed.
