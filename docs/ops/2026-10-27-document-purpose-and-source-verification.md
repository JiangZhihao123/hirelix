# 文档用途与备注引用：根因及验收

日期：2026-10-27 至 2026-10-28。继续处理前次 Agent 重构浏览器验收留下的报告类型与原备注引用问题。仅本地隔离环境，不推送或部署。

## 根因

前次 Chrome 文档 `db143548-bde9-44b2-99a1-3d6da27022c2` 的实际持久状态是 internal、search_update、固定日周期；三条原始备注没有事件时间或发生日期。不是上传丢失或备注不存在。

1. `save_document` 继承旧准备接口的两个类型 submission/search_update，另有独立 audience，却没有表达普通内部工作材料的类型。把内部比较选成周期报告是模型选择，但接口本身不能清晰表达全部已承诺的文档用途，不能只归因于模型。
2. `selectedDocumentRecord` 把周期报告的所有引用都等同于“本期活动”，对每一条来源执行 `recordWithinPeriod` 并拒绝历史或无日期资料。引用背景证据并不等于宣称该事件发生在报告周期内。
3. 修改接口只能改正文、元数据、人选及来源，不能原位纠正文档类型和周期。即使原始资料完整，也只能绕开来源或另造文档。将备注的发生日期改成导入时间会制造事实，不是有效修复。

上述问题均有持久数据和所属服务代码作为依据；不根据姓名、标题、平台、备注内容或单次回复新增分支。

## 通用契约

- 在现有 Deliverable 对象中增加 brief，承载非周期内部工作材料；没有新增表、业务工作流或 Agent。submission 保留候选推荐含义，search_update 表达实际周期报告，受众与用途分开。
- 草稿可在同一对象、版本锁和事务中修正用途与周期；未指定字段保持不变，清除需明确 null。旧版本及已发布快照保留；修改不是发布、发信或撤销链接的授权。
- 明确选定且符合用户、职位、人选范围的来源可以引用。服务保留真实事件时间、日期精度，并计算与报告周期的关系；日期未知与周期外不同。背景证据不算本期活动，导入/创建时间不替代事件发生时间。
- 修改周期时基于已保存的证据快照重算时间关系，不用当前记录覆盖未请求更新的旧来源。
- 定时报告原有的周期选源、来源版本 allowlist、租约和授权约束保持不变；手动选择背景资料的能力不自动扩大长期委托范围。
- Brief 可复用所选候选人原始 CV 的归属与哈希规则，不进入推荐交付或客户反馈。类型转换不静默丢弃附件。客户端显示原始事件日期和背景关系。

## 验证记录

### 本地直接契约

隔离库 `hirelix_workspace_qa_coldstart_20261027`，只使用随机测试 owner。新增 `workspace-document-purpose.test.ts`，与文档写入、来源回归共 3 项通过：无候选人的内部简报、所选原始 CV、周期内/周期外/未知日期、跨时区与日历日期、等价 offset 不增版本、原位切换用途、保留未更新来源的原快照、归属/版本拒绝、已提交副本不可改、旧分享快照不变且不再标为当前副本、brief 禁止发布/记为推荐交付。

首跑真实发现 PostgreSQL 时间戳文本再次进入 ISO 输入校验会失败；在文档服务将已存时间规范化用于校验与比较，等价时间表示不制造新版本。时区显式清空时按既有 UTC 默认重算日期，避免残留旧时区本地日期。旧快照缺少日期证据不冒充“原记录明确无日期”，也不读取当前版本补写旧快照。

原失败日志保留于 `/tmp/hirelix-agent-20261028-evidence/document-purpose-pg.log`；最终 3/3 通过日志为同目录 `document-purpose-pg-final.log`。另有实际工具回执/授权模型/PG 回归 1 项通过；内部角色简报的旧测试 fixture 改用合法 brief 类型，未放宽 submission 的候选人要求。定时协议的选源范围、静默、幂等和暂停约束回归 1 项通过。
