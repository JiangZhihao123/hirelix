## 尚存问题及影响

1. **邮箱恢复说明不准确。** Outlook 已知提供商错误为 ErrorAccountSuspend，但设置页提示 Reconnect this mailbox to renew sending access。重新授权不能等价解决账号暂停，容易让用户反复操作。应保留提供商错误类别，分别解释账号验证、授权过期、权限不足和暂时失败。用户已暂停该账号排查，本轮未再次尝试发送。Gmail 读取仍未开放，设置页对此有明确说明。
2. **首屏对第一次具体工作指导偏弱。** 现有新会话主要是开放式输入和添加资料；有经验的用户可以直接交代任务，首次接触者可能不知道该交什么资料、将得到什么。建议在空白起点给一个具体、可编辑的工作示例，例如带 JD 和 2–3 份 CV 做比较，不建立强制导入向导或固定流程。此项为体验判断，本轮未做真实陌生用户可用性测试。
3. **留存统计尚未围绕 Personal Agent 工作结果。** analytics 事件与 ops conversion 仍主要围绕落地页、登录、旧 search 和付费；未发现当前 workspace 的首次成果、查看成果和跨日继续工作的完整漏斗。可以从现有 jobs/会话/业务记录计算执行与回访，再补最少量成果查看事件；不需要新分析平台或实体。近期 chat 活跃账户仅 1 个，且为本轮 QA 账户，不能据此计算真实用户留存。
4. **输出仍偏长。** 本轮提纲事实总体正确、可使用，但滚动较多，末尾继续附加制作表格的邀请。建议默认先给简洁行动摘要，详细问题保留可阅读内容；不应以删证据换简短。

## 推广与验证方式

可以以“用自己的 JD、简历和沟通记录完成比较、推荐并持续跟进”作为首发核心承诺。先招募一小批真正手上有职位和候选人资料的猎头，观察其独立完成工作，而非只做演示和邀请注册。

推广前至少明确记录：注册、首次提供资料、首次可用成果、成果查看/使用、不同日期继续工作、失败与退出所在环节。首次可用成果应是与职位相关的比较、沟通准备或推荐交付，问候、创建空记录和后台索引不计激活。回访应要求继续真实工作，页面打开不计工作留存。排除内部 QA 账户和自动后台执行。

首批用户观察重点：不需口头教学能否开始；第一次交付是否直接可用；下一次有工作时是否主动回来；不回来是没需求、不会用、结果不可信、等待太久还是邮箱边界。没有真实 cohort 的观察结果之前，不给出留存率或扩大投放的确定承诺。
