# Hirelix 1.0.0 投流上线目标

建立日期：2026-10-20。状态：推进中，尚未放行。

## 唯一目标

让一个首次接触 Hirelix 的真实猎头，从广告进入网站后，能够独立完成注册、开始工作、获得并使用成果、付费、持续跟进，以及管理订阅。首版对外承诺的功能全部可用，关键异常可以理解和恢复，工程侧有可核对的真实证据，达到可以开始投流推广的标准。首个发布版本为 **1.0.0**。

“全部可用”覆盖当前首版桌面端产品承诺，不无限扩展功能。Gmail 暂不支持读取、支持发送；Outlook 支持读取和发送，必须分别验证真实能力并在界面准确说明。微软发布者验证按用户决定暂缓；如果提供商限制阻断目标用户授权，应作为发布阻塞如实记录。已退出的外部付费人才寻访和移动端不属于本版。

## 推进方式

1. 先核对代码、部署版本、现有证据与可见功能，建立明确缺口，避免盲目重复付费或发信。
2. 按自然猎头任务串起完整场景，实际操作、截图、检查下载文件，再用数据库与日志核对。
3. 发现工程缺陷，在真正 owner 修复；完成适当回归和中文 Git 提交，再复测原场景。
4. 汇总候选版本，完成真实生产部署后的端到端复验。生产状态不能由本地通过替代。
5. 所有放行项具备证据且无阻塞后，记录部署提交、版本与已知限制，再将目标标记完成。

继续执行已授权的检查、修复与验证，不逐步请求重复确认。登录/验证码、实际付款、扩大敏感访问等必须用户参与的步骤，准备好具体页面与必要信息后再交接。测试邮件仅发给明确的自有测试收件人，保持少量、正常内容，禁止批量营销式测试。本目标不授权启动广告、增加投放预算或向真实候选人/客户群发。

## 放行与责任边界

阻断核心任务、错误扣费/权益、数据丢失/越权/泄露、重复发送，以及界面声称成功但实际失败，均阻塞发布。不能用 mock、隐藏错误或缩小原定首版承诺包装通过。提供商不支持的能力必须明确呈现，不能假装可用。

模型的业务判断与最终招聘结论按 AGENTS.md 的工程责任标准单独观察；不因一次答案不佳写死流程或堆案例逻辑。投流放行代表工程可用，不保证广告回报、留存率或模型每次判断正确。
