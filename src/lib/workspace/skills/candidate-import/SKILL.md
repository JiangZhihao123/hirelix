description: Bring historical candidates and related records from supplied files and exported recruiting data.

Let the user's instruction and actual material determine the work. Import is not a prerequisite for public research or other useful work. These methods are guidance, not a mandatory sequence.

Inspect relevant file inventories, headers, samples and source identifiers to understand coverage. Distinguish candidate lists, client contacts, roles, notes, relationship exports and attachments. A platform name does not establish a layout; do not interpret all tabular rows as candidates.

Use existing readers and libraries for formats. Use the isolated working environment to apply explicit, repeatable transformations across consistent rows; keep natural-language understanding and uncertain identity decisions with the model. Do not invent regex or keyword rules to judge candidates or infer hidden facts.

Relate files and records only through supported identifiers or other reliable evidence. Retain original paths, fields, dates and source positions. A file is not automatically a CV, and an imported stage or historical interest is not current permission or availability. Ambiguous associations remain explicit.

For authorized persistence, save_records_batch accepts normalized JSONL for one declared internal operation. Obtain its current operation schemas through references/batch-format.json. Source references are evidence locations, never authorization. Save derived data using persistent file_id and sha256 before submitting it. Use single-record tools when appropriate; batch processing is not obligatory.

Use actual per-item receipts to distinguish saved, unchanged, conflicting, failed and unprocessed work. Read or process a receipt file to recover returned IDs for subsequent related records. Completed chunks remain saved after interruption; resume the original job with its immutable input rather than duplicating it. Do not claim a whole backup was restored merely because candidate rows were saved.

Keep unsupported or unnormalized material available in the original sources and explain its practical limits. A retained original field is not necessarily a searchable profile fact, saved communication, role or relationship.

Export instructions and plan restrictions belong in references/platform-exports.md. They are dated reference facts, not executable adapters. Check current vendor documentation when the details matter. Users need not know database fields or prepare a standard template. Ask only about material conflicts or missing decisions that prevent correct work.
